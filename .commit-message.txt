feat(auth): change-password endpoint + Settings UI

POST /v1/auth/change-password (authenticated) verifies the user's current
password, hashes the new one, and revokes every OTHER session belonging
to the user — keeping the caller's own session alive so they don't get
bounced out mid-flow. The current-password check defends against
access-token-theft pivoting to a permanent password change.

API changes:
 - changePassword() helper in auth.service.ts
 - new AuthError code 'wrong_current_password'
 - POST /v1/auth/change-password route, Zod-validated, min(12) on new
 - rejects same-as-old with 400 same_password
 - returns 403 wrong_current_password vs 500 on real errors

Web changes:
 - Settings page: ChangePasswordPanel replaces the placeholder, with
   live validation (length, mismatch, same-as-current), correct
   autocomplete tokens, and clear ok/error feedback.
 - PasswordField helper to keep the three inputs consistent.

Other-session revocation is silent — callers using a different browser
just get 401 on their next refresh and bounce to /login. This is the
expected security UX for "I changed my password" flows.
