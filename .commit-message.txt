fix(gigtech): widen SA fallback to all 4xx and to VCO admin endpoints

Extends the per-customer service-account tolerance from commit 86e0b45.

Two issues that were still breaking the operator dashboard:

1. /admin/audits and /admin/invoices (used by the dashboard's `/summary`
   endpoint and the audits page) hit /admin/* paths, which per-customer
   SAs can't reach. listVcoAudits and listVcoInvoices now catch the 4xx,
   detect the service-account scope, and fall back to the per-customer
   variants — so the operator dashboard's "this month" tile and audit
   log render against the SA's own customer instead of erroring out.

2. The catch range in getMe / listCustomers / listLocations was too
   narrow (specific 401/403/404). gig.tech can return other 4xx codes
   for the same "wrong token shape" condition. All four methods now
   catch any 4xx and trigger the SA fallback.

Caveat we'll learn about: if gig.tech rejects /customers/{cid}/audits
or /customers/{cid}/invoices for the SA too, listVcoAudits and
listVcoInvoices return [] silently. That's the right UX (dashboard
mounts with empty tiles) but worth surfacing to the operator with a
"scoped" badge later.
