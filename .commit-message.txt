fix(web): apply Railway lessons to web Dockerfile preemptively

Two changes that mirror what bit us on the API side, applied to apps/web
before we deploy it (instead of after).

1. Build @octera/shared before next build. With main → ./dist/index.js
   (post-workspace-build commit ac4da5a), Next can't resolve the package
   at build time without the dist artefact, even with transpilePackages.

2. Default HOSTNAME to "::" (IPv6 dual-stack) so Railway's internal mesh
   can reach the Next server. 0.0.0.0 produces silent 502s at the edge.
