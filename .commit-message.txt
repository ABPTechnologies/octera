fix(api): SameSite=None on refresh cookie for cross-site auth

The refresh-token cookie was set with SameSite=Lax. With the web on
jubilant-victory-production-babf.up.railway.app and the API on
octera-production.up.railway.app, browsers refuse to store a Lax cookie
returned from a cross-site POST — so signup/login worked (access token
in body) but refresh would always fail and the user would get logged
out at the 15-minute access-token TTL.

Set SameSite=None in production (still Secure=true, still HttpOnly).
Dev keeps Lax because secure+none over plain http://localhost is
rejected by browsers.

The web's API client already sends credentials: 'include', so no web
change is needed for the cookie to ride along on /v1/auth/refresh.
