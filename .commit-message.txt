fix: compile workspace packages to dist (production module resolution)

Production boot was hanging silently — Railway showed "Initializing"
indefinitely, edge returned 502 "Application failed to respond", and
the deploy log stopped at "No pending migrations to apply" with no
output from `node apps/api/dist/index.js` ever.

Root cause: @octera/db and @octera/shared shipped with package.json
"main" pointing at .ts source. tsx hides this in dev. In production
node sees `./src/index.ts`, fails with "Unknown file extension '.ts'"
at module load, and exits before pino can emit a single line.

Fix:
- packages/{db,shared}: add tsconfig.json, build script, and point
  main/types/exports at compiled dist/.
- pnpm-lock.yaml: register typescript as devDep on packages/shared so
  --frozen-lockfile is happy.
- apps/api/Dockerfile: build @octera/shared then @octera/db before
  building @octera/api, and copy dist/ (not src/) into the runner.

Local dev still works because the deps stage installs all deps and the
builder runs the same `pnpm --filter <pkg> build` chain — `pnpm dev`
resolves through the same package.json so a one-time `pnpm -r build`
keeps tsx watch happy in dev too.
